Manual recovery acceptance checklist

  1. Identify and record the currently served Production commit and customer-facing incident.
  2. Confirm a previous successful Production deployment, its exact Git commit, verified Build 430 receipt and Cloudflare deployment identity.
  3. Rehearse the source and public asset differences; examine all Functions, schema and environment changes before deciding whether code-only recovery is safe.
  4. Obtain explicit owner authorization for the exact rollback candidate; prepare a separately reviewed Git PR and ensure the current Development gate can protect it.
  5. Never copy Development or old Production D1 into current Production, overwrite private R2 media, replay Etsy requests, or silently change shipping restrictions.
  6. After a separately authorized deployment, compare the Cloudflare control-plane receipt, custom-domain source marker and public smoke results before claiming GREEN.

This plan deliberately has no Rollback button. Historical successful workflows alone do not authorize an environment change, and missing evidence remains UNKNOWN.
