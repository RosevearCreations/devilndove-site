Devil n Dove Creator & Operations Help Centre

Use this page as the current operating guide for Creator roles and higher-access workspaces. The circular ⓘ beside a page or control explains purpose, prerequisites, authority boundaries, what changes, what does not change, and the next safe action.

How to use Creator & Operations help

  • Page-level ⓘ: every meaningful operating screen receives a shared page explanation when the help runtime is active.
  • Local ⓘ: complex terms, fields and actions keep more specific contextual explanations beside the control.
  • What happens next: help should identify prerequisites, owning workspace, review state and the next valid action without performing it.
  • Recovery: a disabled, failed or HOLD state should point to the evidence or workspace needed to move forward rather than encouraging duplicate records or blind retries.
  • Help is always read-only: it does not save, publish, post accounting, change Inventory, call providers, run migrations or alter Production.

Start → Work → Review → Finish & recovery

  • Start: open the existing authoritative record first. Create a new record only when the real business object does not already exist.
  • Work: use the owning workspace for the fact you are changing; hand off identifiers/references instead of copying authoritative records.
  • Review: resolve prerequisites, evidence gaps, warnings and HOLD states before a high-consequence action.
  • Finish: use the explicit save, approve, post, publish, issue, close or promote action and retain the resulting evidence.
  • Empty state ≠ broken state: “no records yet” may be normal; a failed request, unavailable provider, stale response or permission error must be recovered before interpreting the screen as empty.
  • Disabled actions: the adjacent circular ⓘ explains why an action may be unavailable and directs you back to the prerequisite/owning workflow. Do not bypass a HOLD or create duplicates to make a button become available.

The page-level ⓘ on Packaging, Product/Media, Creative/CAIP, Custom Work, Inventory/Tools/Supplies, Finance, Operations and I.T./Release screens now includes task-specific recovery guidance.

Accounts, passwords and security

  • Stored passwords are one-way hashes and cannot be displayed. Eye controls reveal only a password currently typed or generated in an input.
  • New password writes use the current salted adaptive hashing scheme. Older compatible hashes are upgraded after a successful verified login.
  • An administrator may issue a temporary password without knowing the old password. Clearing the target user’s other sessions is the safe default.
  • Never place passwords, session tokens, API tokens, signing secrets or private keys in visible help, logs, D1 reference fields or screenshots.

SEO, Google and search engines

  • Every indexable public page must expose exactly one H1, one useful title, one useful meta description and one clean HTTPS canonical URL.
  • Internal search, account, cart, admin and empty template surfaces must not compete with real public content in search results.
  • The sitemap contains canonical indexable public destinations only. Product detail shells are excluded; real product URLs set product-specific canonical metadata at runtime.
  • Open Graph, social preview metadata, descriptive image alt text, crawlable links and valid JSON-LD support discovery without keyword stuffing.
  • Mobile and desktop must expose equivalent important content; do not hide essential product facts or headings on the phone layout.

Phone, tablet, PC app and web layout

  • The shared responsive layer protects 360–390px phones, tablet widths, laptop/PC layouts and wide desktop web layouts.
  • Navigation and card grids must wrap instead of forcing page-level horizontal scrolling. Images and media stay within their containers.
  • Wide data tables use their own horizontal scroll region. Touch controls keep a practical minimum target size on coarse-pointer devices.
  • When adding a new interface, verify it at phone, tablet, 1024px desktop and wide desktop widths before considering it complete.

Development, release and Production

  1. Make application changes in Development.
  2. Pass source quality, database safety, responsive/search checks and the exact Development Preview acceptance.
  3. Promote only the exact green Development tree to main; do not create a main-only application patch.
  4. Production independently snapshots business data, proves canonical D1 convergence, deploys the exact main SHA, verifies bindings and runs public smoke acceptance.
  5. If any Production proof fails, Production remains on hold until the owning problem is corrected and the full proof is rerun.

External services and HOLD states

Configured does not mean tested. Stripe, PayPal, social OAuth, private-media acceptance and Cloudflare Access service-token work remain separate evidence lanes until a current real acceptance proves them.

Do not mark an external lane passed because environment-variable names exist or a provider page can be opened.

Product images, crop and focal point

  • Buyer-facing Product cards and Product detail pages show the complete uploaded image by default. Portrait and landscape images may have intentional empty space around them rather than being cut off.
  • Use Product Media & Image Editor when you deliberately want to crop, resize, replace, reorder or re-centre an image.
  • Keep original preserves the uploaded file. Square and landscape presets deliberately create a modified file.
  • Focal point records where the important subject is located for intentional presentation or derivative work. It does not authorize an automatic Storefront crop.

Today Needs Attention and runtime incidents

  • Start with the What, Where, Age and Owner information. The exact endpoint and incident scope identify the failing area.
  • Grouped recurring incidents help identify one repeated cause instead of treating every row as a separate problem.
  • Fix the underlying cause before resolving related incident records. Ignore is reserved for a known harmless condition.

Using the ⓘ contextual help system
