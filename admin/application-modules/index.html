Application Modules

Control the three top-level Devil n Dove application modules. Disabling a module blocks its direct surface and runtime activation; reviewed shared service contracts can remain available to another enabled module that explicitly depends on them. No switch deletes business data.

Current design: Application Core + Commerce & Operations + Creative & Production + Business & Administration.
Safety: this page and its control API remain in shared core so an administrator can recover from an accidental module disable.
Dependency rule: only explicit reviewed service contracts may cross a disabled owner-module boundary, and only while an enabled consumer is authorized.
Background rule: module-owned polling/sync/provider work must check the background permission before running; disabling a module clears that permission.
Authenticated acceptance: temporarily exercises audited module controls and one Admin read-level guard, automatically restoring every changed module/role in a finally path. Shared tests are read-only; no dummy Inventory movement is created.

Role access

Current account roles are member and admin. Build 438 does not invent additional staff roles. Future operator/creator roles can be added deliberately when the user model supports them.
