# Build 260 Validation — Media Studio 503 / bounded request hardening

## Problem reproduced from production report

The live browser requested:

`GET /api/admin/media-content-studio?path=/&limit=180`

and received HTTP 503. Build 259's GET handler combined page slots, up to 180 media records, assignment-count correlation, page-directory aggregation and optional selected-media uses in one authenticated request.

Build 260 removes that all-in-one request path. The production 503 cannot be conclusively attributed to Worker CPU/memory or D1 load from the source ZIP alone, but the previous request performed substantially more D1/result work than the explicit-slot UI needs.

## Build 260 runtime changes

- `mode=page`: returns only active explicit slots for the selected static page.
- `mode=media`: runs only when **Choose image** opens; returns 48 records by default, server-capped at 72.
- `mode=uses`: returns usage locations only for one selected media ID.
- Removed `Promise.all` from the Media Studio GET bootstrap.
- Removed the correlated per-media assignment-count query from library listing.
- Added keyset pagination using `media_asset_id < before_id`; no large offset paging.
- Search/filter refreshes only the open image picker, not page slots.
- Product/finished-product, inventory, supplies and tools remain excluded server-side.
- The API defaults to compact `page` mode when an older cached client omits `mode`, so the old Build 259 URL no longer triggers the heavy bootstrap path after the API is deployed.
- Handled Media Studio query/update exceptions return structured HTTP 500 JSON (`media_studio_query_failed` / `media_studio_update_failed`) instead of application-generated 503 responses, so a remaining Cloudflare 503 is easier to distinguish from a D1/schema/code exception.
- No D1 schema change. Migration boundary remains Build 259.

## Expected production network sequence

Opening `/admin/media-content-studio/` on Home should now issue a small request similar to:

`GET /api/admin/media-content-studio?mode=page&path=%2F`

Opening **Choose image** should then issue:

`GET /api/admin/media-content-studio?mode=media&limit=48`

Selecting **Details / uses** should issue:

`GET /api/admin/media-content-studio?mode=uses&media_id=<id>`

The old `path=/&limit=180` combined bootstrap should no longer be generated by the Build 260 browser bundle.

## Deployment

1. Do **not** apply another D1 migration if Build 259 is already installed.
2. Deploy the complete Build 260 package.
3. Hard-refresh `/admin/media-content-studio/` and confirm `admin-media-content-studio.js?v=260` is loaded.
4. Confirm Home loads before opening an image picker.
5. Open one image slot and confirm the 48-item media request succeeds.
6. If the small `mode=page` request still receives a platform-generated 503, capture the Cloudflare Ray ID and Pages Function log for that exact request before changing application logic again.
