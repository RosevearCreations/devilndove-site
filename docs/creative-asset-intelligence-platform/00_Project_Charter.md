# 00 — Project Charter

## Vision

CAIP is the creative operating record for Devil n Dove: every completed project can become a controlled set of retained media references, verified facts, story evidence, reusable creative candidates, and reviewed publication inputs.

## Business outcome

A finished product should no longer leave photos, clips, notes, materials, and useful lessons scattered across phones, folders, the product editor, and social drafts. The team should be able to open one project and answer:

- What exists?
- What is safe to use where?
- What do we actually know?
- Which media best supports a specific purpose?
- What can be reused for a product page, gallery, Journal entry, YouTube plan, Reel, TikTok, listing, or educational record?
- What remains only internal or still needs consent/review?

## In-scope source families

| Source family | Current state | CAIP treatment |
|---|---|---|
| Devil n Dove product | Live | Primary Build 201 source; linked through Content Studio |
| Product images | Live | Canonical source references; never copied/reordered/deleted |
| `media_assets` / R2 objects | Live | Referenced via existing asset/product links; future private-object adapter only |
| Content Studio media | Live | Current ingestion boundary and source-safety authority |
| Content Studio deliverables | Live | Future downstream context; not modified by CAIP |
| Content Release Board drafts | Live | Downstream public-release authority; not modified by CAIP |
| Detailing job media | Planned | Future source adapter after live privacy/consent/job controls exist |
| Handmade process logs / material records | Planned | Future evidence adapter; not invented by CAIP |

## Non-goals

- CAIP must not replace inventory, costing, product, consent, product gallery, Content Studio, Release Board, R2, social queue, or the future renderer.
- CAIP must not publish content or accept a recommendation as a release decision.
- CAIP must not infer facts from media as sale claims, material claims, before/after claims, accessibility descriptions, or consent decisions without a configured provider, evidence provenance, and human review.

## Success measures

The first live success is not “AI generated 100 posts.” It is one real completed product where the team can safely trace every candidate asset and story statement back to a retained source record, approve the right ones, and release a truthful page without losing a photo/video.

## Roles

| Role | CAIP responsibility |
|---|---|
| Admin/owner | Final source/right/evidence/segment review; internal CAIP approval; chooses downstream releases |
| Content reviewer | Curates source candidates and adds review notes; cannot invent public rights |
| Future editor/renderer provider | Receives only approved export input, never a blanket media grant |
| Future auditor | Reads immutable event/run records and manifests |
| Public visitor | Has no CAIP access; sees only separately published content |

## Build 201 charter decision

Build 201 implements the control plane before any external intelligence/rendering provider. That sequence avoids repeating prior media-loss and accidental-publication risks.
