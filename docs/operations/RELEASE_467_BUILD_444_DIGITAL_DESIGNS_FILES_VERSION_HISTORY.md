# Devil n Dove — Build 444 Digital Designs, Files & Version History

**Release 467 · 2026-10-23 · Maker queue**

## What this build adds

- `/admin/project-design-files/` is an operator-only design-file workbench linked to existing `creative_work_projects`, `creative_work_outputs` and the Admin Work Orders navigation. No parallel project ledger, Product, sale, Inventory entry, or publication is created.
- Private original CAD/CAM and reference files (STL, 3MF, SVG, DXF, G-code/NC, STEP/STP, OBJ, PDF, JPEG/PNG/WebP and ZIP) are stored in the **existing private** `CAIP_PRIVATE_MEDIA_BUCKET` R2 binding, with unique immutable object keys, SHA-256 byte fingerprints, strict extensions, attachment-only authenticated downloads and a 12 MiB/file ceiling. We do not fall back to a public bucket.
- A permanent design key, sequential revision and explicit latest-parent reference preserve a failed first file after a corrected second revision. The new canonical D1 migration `0040_release467_maker_design_file_revisions.sql` enforces append-only originals, reviews and output link history and same-project lineage.
- Owner review is deliberate and separate: `needs_changes`, `rejected`, or `approved`, with a factual 12+ character note. Approval requires a file explicitly marked ready and either our own original work or documented licensed rights. Unknown/third-party references remain on hold; the system never infers permission or successful machine results.
- Approved exact file revision IDs can be explicitly associated with an existing canonical project output. Replacing an older output reference requires a separate checkbox and note; the prior link remains visible. Linking does **not** assert physical manufacture or change output status.
- The server authenticates every request, requires same-origin writes, limits project list/history reads, checks project ownership, and audits manual upload/review/output-link/download operations. No files or links go to Etsy, Facebook, Storefront, Product media, printers, CNC equipment, or CAIP public content automatically.

## Owner acceptance — one real design, one failed version and one output

1. Open **Admin → Work Orders → Digital Designs**, or go directly to `/admin/project-design-files/`; choose an existing Creative Project.
2. Under a new `design_key`, upload a private file and note the source, licence, machine readiness, and revision note. Verify the file appears as revision `r1` with a SHA-256 fingerprint and no automatic approval. Download the private original and check it matches.
3. Deliberately mark that first revision `needs_changes` or `rejected` with factual notes. Select that exact latest revision as parent and upload the corrected design. Confirm `r2` exists *alongside* `r1` (not in place of it).
4. Mark `r2` **Ready** *when uploading*, and use the review form to approve it if our source/rights really permit manufacture. A third-party reference or unknown source must remain on hold until rights are established in a new, corrected revision.
5. In existing Creative Process, create or select the real project output representing the physical object. In Digital Designs, select that output and `r2` and record the explicit reference. The displayed link must include the exact SHA-256. If changing the linked revision, tick the replacement acknowledgement; the earlier assignment must remain visible.
6. Verify no Product, stock, storefront, Etsy listing, Meta posting, manufacturing completion or public project is generated by this process.

## Boundary and operational notes

- New canonical D1 migration **40** must be applied and checksum-proven first on Development, then Production, by the existing release workflows before the new API is considered ready. No request-time DDL or new secrets are introduced.
- Private original R2 availability is checked at upload/download. If absent, the UI/API returns `PRIVATE_BUCKET_REQUIRED`; **no public fallback**.
- Upload receipt keys prevent retry-created duplicate revisions for the same actor/content. If object upload succeeds but D1 insertion is unconfirmed, the private object is intentionally retained for manual recovery; do not delete originals automatically.
- Review/output links are append-only and intentionally never overwritten. A revised design does not silently update already-linked outputs.
- The admin view limits reads to 120 design revisions / 100 canonical outputs / 120 links per project; oversized histories require a dedicated pagination/archival follow-up rather than silent truncation.
- Rollback: disable the Build 444 UI/API; preserve all private R2 files and immutable audit records. Repair via a new forward-only migration; never edit the applied migration or remove source files.
