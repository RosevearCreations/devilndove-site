# Build 621 — Original full-history checkpoint, Meta authority handoff and real TEST witness

**Deployment of code does not activate external trust.** Required D1 proposals `0052`–`0059` remain **PROPOSED ONLY** and are **not applied by a GitHub merge or Cloudflare Pages deploy**. A successful source release is not evidence of genuine Etsy/Meta connectivity, migration approval, an external signed checkpoint, or witnessed Meta receipt.

## What Build 621 actually adds

1. Server hashes **every source row**, in ascending SQLite `rowid` order, for all six immutable Etsy TEST source tables: grants, one-time attempts, outcomes, witnessed acceptances, failed nonce custody, and failure dispositions. Per-table SHA-256 hash chains are combined into an exact full-history digest, never a `LIMIT 100` excerpt. Start/end row counts and final row IDs must agree; incomplete, changed or oversized scans **fail closed**. The summary excludes customer and token fields.
2. Original **ISSUER**, separate **WITNESS**, and **OWNER** must sign exactly the same canonical, current-history payload using three distinct **active, independently pinned Ed25519 keys**. The verified original issuer, a witnessed existing external readback, the approved custodian origin, the whole-history row counts, the current owner-ledger head, and the external receipt SHA-256 must all agree. Signed evidence is inserted in an **immutable table**. The resulting state is **`ORIGINAL_HISTORY_SIGNED_EXTERNAL_ARCHIVE_READBACK_PENDING`**, not falsely described as archived outside the application.
3. A read-only original Meta authority handoff shows the original source registration, saved Page ID and its provider permissions candidate, recent real one-use GET receipts, spent attempts, signed Etsy checkpoint records, and witness acceptances. It has **no enroll/approve key endpoint**, does not return OAuth tokens, and never calls Facebook/Instagram.
4. Only an **existing real Meta Page GET** (Build 620's exact `GET /v26.0/{approved_page_id}?fields=id`) with a previously spent one-use nonce, saved matching Page ID and immutable response digest, valid original source/grant signatures and independent issuer/witness/owner receipt signatures may be accepted. Failure receipts, missing results, revoked keys, mismatched pages, changed OAuth scopes, stale complete-history hashes and repeat witness receipts are denied. Accepted state is **`WITNESSED_ONE_META_PAGE_ID_GET_NO_CONNECTED_CLAIM`**: never public posting/Marketplace/Instagram approval.

## Step-by-step original owner / independent operator handoff

1. **Ree / original source computer:** Confirm the exact released source and backup/restore custody. In admin **Channel Trust → Section 42**, choose **Review original Meta issuer enrollment handoff**. Do not paste secrets, original private keys or bearer tokens into the console. If the endpoint says migrations unavailable, stop: independently authorize and execute proposed D1 migrations `0052`–`0059` in order, with original operator/owner approval and verified backup restoration first.
2. **Independent external issuer/witness:** Retrieve the official original Meta Page source and trust-pin fingerprints directly through the original owner/provider authority, not from an untrusted app screenshot. Use the separately governed `dd620_meta_original_source_registrations`, `dd614_authorities`, and externally provisioned `DND_614_VERIFIED_PUBLIC_KEY_PINS`. There is **no** button that enrolls or activates a key. Reject false/shared/revoked authorities. Have the independent operator verify original source before separately approved Meta grants are installed.
3. **Owner review of complete Etsy history:** In Section 42 choose **Compute COMPLETE immutable Etsy history SHA-256 checkpoint**. Review `full_source_snapshot`: six table counts, per-table hashes, aggregate `history_sha256`, `counts_sha256`, and owner-ledger head/sequence. This calculation is **read-only** and **does not contact Etsy or Meta**. Resolve any anomaly/partial scan before signing; a new receipt means a new digest is necessary.
4. **Original externally signed checkpoint:** Create the signed bundle with *exact fields* specified by `HISTORY_621` in `functions/api/_lib/trustHistory621.js`. Bind `history_sha256`, `counts_sha256`, current `ledger_head_sha256`, `ledger_sequence`, original `checkpoint_sha256` and source fingerprint, original custodian `external_receipt_sha256` and a verified HTTPS `external_custody_ref`, exact decision `ATTEST_COMPLETE_IMMUTABLE_ETSY_HISTORY_NO_PROVIDER_ACTION`, a fresh nonce, and 30-minute maximum valid issued/expires times. Original ISSUER, independent WITNESS and OWNER each sign the same canonical JSON text using separate original private keys **on their own devices**. Supply public signatures only. Use **Record three-party signed COMPLETE Etsy history checkpoint** plus admin password; do not do it until the genuine signatures exist. The result is signed but still awaiting independent archive readback.
5. **First genuine Meta TEST:** Only after the original Meta issuer is independently enrolled, the grant is separately approved, and the saved Page OAuth scopes/Page ID are current, use Build 620's single pre-approved read-only Page GET. This consumes its nonce before the network call; failed/ambiguous requests must **never be retried with the same nonce**. Confirm the genuine `dd620_meta_test_outcomes` receipt, which is only produced after provider HTTP 200, exact JSON Page ID and digest validation.
6. **Witness acceptance:** Have the original ISSUER, independent WITNESS and OWNER sign `META_ACCEPT_621`, binding the original grant/nonce/approval digest, actual stored receipt hash, exact Page ID, original external checkpoint, current signed all-history digest, `WITNESS_ONE_ACTUAL_META_PAGE_ID_GET_ONLY_NO_PUBLICATION`, and fresh signed times/nonce. Submit public signed JSON via **Witness existing genuine Meta Page GET receipt**. This **never performs another provider GET**. If no real receipt exists, status must stay HOLD.
7. **Independent external archive readback:** Verify a fresh signed copy of the full-history digest with the actual external custodian outside this application. Build 621 does **not** grant itself that independent status. Any production write, publication, extended API scope, new original key or live customer communication requires separate scoped approval.

## Exact signature JSON wire formats

`signed_bundle` is `{ "payload": { …exact field order/values… }, "signatures": [ { "role": "ISSUER", "authority_id": "…", "signature": "…base64url-ed25519…" }, { "role": "WITNESS", … }, { "role": "OWNER", … } ] }`. The `signature` covers the exact canonical payload returned by `canonicalHistory621` or `canonicalMetaAcceptance621`, **not** the outer wrapper. Different role identities/keys and current independent pins are mandatory. `nonce` is never a password or API token. The UI posts same-origin, requires admin login/password recheck, and does not create proof on the user's behalf.
