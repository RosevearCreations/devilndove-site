## Product Entry 2.0 — one canonical Product, four areas

1. **Details:** name, stable Product ID, SKU/slug, type, category, CAD price, inventory, description and status. Inline required-field badges explain which destination requires what. A draft's readiness is not represented as overall Product completion.
2. **Recipe:** the existing saved soap-base, fragrance and additional-oil catalog selections feed the official INCI candidate list only when source INCI is verified. Record source IDs/revisions, original ingredient order, measured bar weight and owner acceptance. Conflicting product name/fragrance or unverified source = explicit HOLD, with a clear owner correction path; never auto-approve label ingredients.
3. **Photos:** one Product gallery; original image IDs and image-source provenance remain canonical. Allow reordering without re-uploading. Explicit alt text, public-use permission, dimension checks, channel eligibility and immutable upload receipts. Use exactly the photo set actually approved for that destination.
4. **Destinations:** one card per target with eligibility, account connection, required-field checklist, remote identity, last confirmed status, exactly one explicit action, and recovery guidance when a result is uncertain. Technical proofs live behind an Advanced disclosure.

One primary **Save Product** writes/read-backs the local Product only. The destinations section must never imply that local Save automatically creates, updates or publishes a remote listing. For an existing verified Etsy listing, the action reads its saved ID and offers **Update existing draft**; only when confirmed absent and permitted may **Create new draft** be offered. Publishing is separate and owner-approved in the remote platform, unless explicit supported and authorized publication is requested later.

### External destination lifecycle contract

| State | Owner-facing text | Allowed action |
| --- | --- | --- |
| `not_configured` | Not connected | Show setup/manual instructions, no posting. |
| `connection_review` | Check account and permissions | Read-only verification, no posting. |
| `needs_product_fields` | Finish highlighted fields | Local edit/save. |
| `ready_for_draft` | Ready to prepare draft | Explicit create only with no existing remote ID and authorization. |
| `existing_draft_confirmed` | Existing draft #ID verified | Explicit update existing draft; never create duplicate. |
| `manual_handoff` | Prepared for manual posting | Copy/export and link to provider, no silent write. |
| `remote_status_unknown` | Outcome uncertain — inspect provider | Block retries pending account-scoped remote readback. |
| `remote_draft_confirmed` | Draft saved on provider | Show confirmed ID/status/timestamp, no automatic publication. |
| `published_confirmed` | Live on provider | Show exact provider ID, URL and verified timestamp. |

Provider capability is **not** inferred from a checkbox. Etsy Open API v3 supports create draft, update listing and image upload with correct OAuth scopes; the listing ID and shop must be read back before reuse ([official Etsy listings tutorial](https://developer.etsy.com/documentation/tutorials/listings/)). Marketplace is manual by default unless the actual business account is eligible for an approved integration. Facebook Page posts and Instagram professional-account publishing are separate Meta capabilities, subject to relevant account permissions. TikTok photo/video draft upload or direct posting requires reviewed app, scoped user authorization and creator/post-status checks ([official TikTok documentation](https://developers.tiktok.com/docs/en/content-posting-api-get-started)). X and Pinterest may have separate API modes; user-scoped token, media rules, rates, app eligibility and remote readback must be verified before enabling a write. Other channels default to manual handoff until proven.

### Remote identity and write guardrails

- The Product record is the source of truth; destination metadata is separate: `product_id`, `channel`, authorized account/shop ID, remote listing/post ID, remote URL, channel-specific copy/tags, last verified status/time and consent evidence.
- Scope remote IDs by Product **and exact owner account**. Never create a second Etsy draft to recover a lost response; inspect saved primary identity and existing remote inventory first.
- Each upload has a source photo ID and an independent provider image ID or unconfirmed/HOLD status. An HTTP timeout is not proof of upload failure and does not authorize retry.
- Explicit consent and receipt readback are required for external writes. No credentials in HTML, static JSON, localStorage or logs. All endpoint writes must be authorized and audited server-side.
- Marketplace, Instagram, TikTok and X are different content types: a social post must not be shown as an Etsy-style purchasable listing. Each card explains what that channel actually receives.
