# Devil n Dove Build 734 — Original Master Receiver Assurance and Customer Account Recovery

## Scope and customer functionality
- Existing login links lead to `/account-help/index.html`, including **Forgot Password** and **Forgot Account**.
- Forgot Password calls `/api/auth/recovery-734` with `action=reset_request`. An eligible active registered user receives a one-time, 30-minute reset link via the existing configured Resend email service, **only at the original registered address**. A random 32-byte token is sent using an email link with a fragment, never stored in source D1 or public web logs. D1 stores only a SHA-256 digest. The response never reveals whether an account exists, was inactive, or an email was sent.
- The received reset link exposes the form using `mode=reset`, immediately removes its token fragment from browser history, then posts `reset_redeem` with 12–128 character matching passwords. The original D1 atomic batch claims one unexpired, issued token, replaces the live user's credential using the existing salted PBKDF2 hash authority, invalidates **all sessions and other outstanding reset links**, and returns a success indication only after original D1 write receipts confirm changes. Invalid and replayed links fail closed.
- For forgotten account/email, an existing contact form records the support request for staff review without identifying an account. A separate reminder submits an email address and sends a simple account-email reminder **only to that identical, verified original registered email**. No alternate address can acquire credentials; no public lookup returns account identity.
- All public recovery submissions have SHA-256-scoped append-only original D1 attempts with per-address and per-IP rolling-hour ceilings, bounded bodies, same-origin checks for browser requests and generic non-enumerating outcomes. They cannot be used to recover admin credentials via an alternate contact identity. The sender never writes email credentials, raw tokens or passwords to D1 or logs.

## Mail provider boundary
**True password-reset delivery requires genuine production `RESEND_API_KEY` and `NOTIFICATION_FROM_EMAIL` (or `RESEND_FROM_EMAIL`/`SUPPORT_FROM_EMAIL`) and a verified sending domain.** The request endpoint fails closed to a generic privacy-preserving outcome when the provider is unconfigured or rejects a send; that does **not** prove the email was delivered. Code/CI cannot claim a live customer inbox delivery without a safe, consented original mailbox pilot. No user input is required to deploy the code.
