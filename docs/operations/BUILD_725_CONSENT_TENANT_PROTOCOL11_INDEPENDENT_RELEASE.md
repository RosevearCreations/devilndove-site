## What Build 725 actually enforces
1. **Pure reusable source-policy evaluator** `assessConsentTenantCapability725` in existing `functions/api/_lib/appModuleRoutes.js`: exact company, tenant, workspace, DND original resource ID and source revision; active identity, appropriate T0–T3 tier, exact company operator/module rights for private media/inventory and explicit original owner write permission for local write candidates. T4/T5 candidates always denied. Unknown capability denied.
2. **Personal-media/private Product consent**: original-source-verified consent ID, matching subject/company/tenant/workspace, exact capability, purpose (`maker_media_review` or `private_storefront_read`), current 24-hour-bounded consent, no withdrawal/revocation. A missing or stale original consent record fails closed. This pure evaluator does **not** fetch the original D1/R2 row, verify a third-party signing key, grant live authorization or propagate withdrawal to actual peers; higher-level calling code must supply **verified** original evidence.
3. **Delegation** for source-only cross-app candidates: exact source `devilndove`, destination app, capability, tenant/workspace/company and consent ID; no subdelegation, T5, authority transfer or owner-gated remote write; expiry at most 24 hours; revoked/expired cases HOLD. Only an enrolled original signed transport, durable replay controls and independent peer response may eventually act on this candidate; none is installed in Build 725.
4. **Compatibility negotiation** `negotiateIndependentSync725`: 1.0 peers are accepted for existing `health.read`/`capabilities.read` only, while newly scoped Product/media/inventory capabilities require 1.1. Protocol 1.2 within major 1 may add optional fields while preserving old known schemas; unknown capability or major 2 is rejected. A missing peer returns `HOLD_PEER_UNAVAILABLE`, `local_operations_continue=true`, `lockstep_release_required=false`.
5. **Real original Admin-route denial**: existing `POST /api/admin/mobile-create-product` and `GET/POST /api/admin/product-distribution-406` now explicitly reject attempted unregistered `X-Rosevear-Delegated-Capability`, `X-Rosevear-Sync-Protocol` or delegated body authority rather than silently accepting the request as local source ownership. Existing, individually authenticated local Product camera/draft and gallery review flows continue under their existing original session, consent/D1/R2 verification and owner gate. This additional denial is **not** a claim that every historic Product, checkout, social, storage or financial route was audited.
6. **Protected Admin visibility**: `GET /api/admin/production-variable-audit-406?review=725` requires a verified active Admin and returns only static compatibility assessment, fail-closed negative, no-store status and clear HOLDs. `/admin/it-integrations/` includes a button to inspect. No D1/worker/peer write or private customer data is returned.
