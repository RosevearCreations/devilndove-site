# Existing authorities that MUST be extended, not duplicated

## Custom Work

Already exists:

- public `/custom-request/`;
- admin `/admin/custom-request/`;
- private reference-image upload;
- budget and requested-by date;
- recipient / occasion / handoff context;
- quote drafts, quote revisions and quote line items;
- payment-request drafts and payment gates;
- order drafts and order-stage events;
- private customer-status journey;
- fulfillment prompts and customer responses;
- public-proof candidate handling.

Therefore Builds 205–224 must **enrich this authority**, not create another custom-request system.

## Creative Project / Creator

Already exists:

- Creative Process / Creative Automation;
- Creative Project idea/objective/story context;
- materials, tools, time, experiments, mistakes, repairs and lessons;
- reviewed material usage and Inventory posting/reversal;
- CAIP media/evidence handoff;
- Content Studio and publication preparation;
- project cost/revenue evidence.

Therefore this roadmap adds **normalized manufacturing operations and production states** to the existing project engine instead of creating a second project-management system.

## Workshop process catalog

Build 156 already owns:

- shared `inventory_processes`;
- one reviewed primary process assignment per Tool/Supply;
- custom process creation.

Therefore this roadmap extends the process catalog and reuses it as the canonical process identity. It must not introduce a parallel process-name dictionary.

## Product / Storefront readiness

Builds 199–204 already own buyer-readiness and launch-set rules.

Therefore this roadmap may add campaign progress, queue ownership and completion metrics, but it must not create a second Product Editor or duplicate readiness logic.

## Product media / CAIP / Media Studio

Existing media authorities remain responsible for source media, Product media, public placement and private CAIP evidence.

Therefore manufacturing operations and knowledge records may reference approved media, but must not create a new image store.

## Packaging Studio

Packaging Studio already owns:

- editable layouts/templates;
- internal proof/version approval;
- physical print/laser evidence;
- Packaging BOM and component costing.

Therefore customer proof work must reuse Packaging outputs when applicable instead of building a parallel packaging proof engine.

## Finance profitability

Existing Finance / Creator ↔ Finance reconciliation already includes:

- material cost;
- tracked minutes;
- labour-cost intelligence;
- packaging cost;
- overhead;
- channel/payment costs where evidenced;
- project profit/margin reconciliation.

Therefore later costing builds enrich source production evidence and feed the existing Finance authority; they do not create a second accounting or profitability system.

# Strategic operating model

Devil n Dove should increasingly support five connected questions:

1. **What can we make?** — capability taxonomy and public capability pages.
2. **How should this idea be made?** — custom-work triage and hybrid manufacturing route.
3. **What exactly are we making?** — versioned proof, prototype/sample and production-run authority.
4. **What did it actually cost and how did it perform?** — detailed production evidence feeding existing Finance.
5. **What did we learn?** — source-backed workshop knowledge that can be reused safely.
