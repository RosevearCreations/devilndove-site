**Production is frozen at Build 280 unless deliberately promoted through the separate Production workflow. Development has intentionally diverged.**

Builds 281–285 established the modular registry, ownership model, active Packaging lifecycle, owner-side read contracts and real contract consumption. Build 286 introduced the admin-protected `/api/admin/packaging-bootstrap` narrow read boundary. Build 287 added the Content-owned managed artwork picker. Build 288 made the old broad Packaging GET unreachable from the active runtime. Build 289 moved Packaging POST transport through `/api/admin/packaging-write`, delegated the mature write implementation unchanged, and proved successful write responses no longer need bulk Catalog or Inventory collections.

Build 290 completes that read-boundary migration at source level. The broad Product `LIMIT 500` enumeration and both broad Inventory `LIMIT 1000` enumeration forms have been physically removed from `functions/api/admin/packaging-studio.js`. The dead `metadataText()` and `mapPackagingInventory()` helpers used only by those bulk reads are removed, and `listData()` no longer returns `products` or `inventory`.

This cleanup does **not** remove legitimate linked context. Packaging project lists and selected project detail may still join the specific linked Product; Packaging components may still join their selected Inventory rows; source-material workflows may verify or link selected Inventory rows; and project creation may read the specifically selected Product and its marked ingredient resources. These are scoped Packaging relationships rather than bulk ownership of Catalog or Inventory.

The mature `onRequestPost` business implementation remains unchanged from final Build 289. `/api/admin/packaging-write` now delegates directly to it without the temporary D1 SQL-filter proxy. The obsolete `functions/api/_lib/packagingWriteBoundary.mjs` migration helper is deleted. The gateway retains the response-shape boundary (`products` and `inventory` omitted) and now reports `legacy_broad_reads_removed: true`; broad-query skip counters are zero because there are no longer broad queries to intercept.

The active runtime still composes Build 286 narrow bootstrap contracts, Build 287 Content artwork selection, Build 288 legacy-GET retirement, and the unchanged Build 289 browser write bridge. Build 290 adds explicit runtime provenance for `legacyBroadReadsRemoved`, `legacyBroadReadRemovalBuild: 290`, and `writeGatewayBuild: 290` while preserving `writeResponseBuild: 289` for the unchanged browser bridge.

Build 290 introduces no D1 migration, SQL/schema change, Wrangler/binding change, R2 enumeration, or Production change. It is a source-cleanup build whose purpose is to remove duplicated cross-domain bulk reads after Builds 288 and 289 proved they were no longer required.

Expected next work after Build 290 parity validation: decide whether to physically retire the dormant legacy `onRequestGet` handler itself or extract the mature Packaging POST implementation into a dedicated Packaging write service so `/api/admin/packaging-write` can become the native write authority rather than a delegation gateway. Persistent Content media-ID provenance for selected Packaging artwork remains a separate explicit schema/contract decision.
